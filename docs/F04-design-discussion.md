- 브랜치: `feat/F04_workout_coaching` (base: dev `f0b3ceb`, F03 병합 포함)
- 기준: Figma F04 캡처 4장(2026-11-20), 기존 `workout-session` 구현
- 갱신: 2026-11-23 (세트 수정 · 자동 일시정지 UI · 보완 작업 반영)
- 원칙: 기존 MediaPipe·판정·카운트·타이머·TTS·저장 로직 유지. 정책·계약이 필요한 기능은 UI까지만 만들고 여기 기록.

## 1. 운동 중 세트 수정 (횟수·시간·휴식)

| 구분 | 상태 |
|---|---|
| UI | `SetEditSheet` — 세트별 목표 횟수(직접 입력), 세트별 시간 ±10초·직접 입력(예: `130` → 01:30), 휴식 ±10초, 키패드 ±5회(시간은 ±10초), 변경사항 저장 / 돌아가기 |
| 규칙 | `routineEdit.ts`(단위 테스트 `scripts/test-routine-edit.cjs`) — 초안에서만 수정, 저장 시 새 루틴 생성(원본 불변). 완료·진행 중 세트 잠금. 범위: 횟수 1~100회, 운동 시간 10초~10분, 휴식 5초~5분. 휴식은 잠기지 않은 세트에만 적용 |
| 적용 시점 | 저장 후 **다음 세트부터**. 이미 돌고 있는 단계 타이머는 바뀌지 않음(`PhaseTimer`는 시작 시 시간으로 진행) |
| DEV 미리보기 | 일시정지 → 종목 `›` → 세트 수정 → 저장 시 Mock 루틴에 반영. 서버 요청·기록 저장 없음 |
| **실제 운동 화면** | 같은 컴포넌트를 쓰지만 **수정 진입(`›`)을 표시하지 않음** — 아래 결정 전까지 저장이 실제로 동작할 수 없음 |

**결정 필요 (백엔드·기획)**

| # | 내용 |
|---|---|
| 1 | 세션 동기화(`PUT /workout-sessions/{id}`)는 시작 시점 `routineSnapshot`을 그대로 보내며 서버가 원본과 대조 검증함(`workoutSessionService.ts` 주석). 운동 중 목표를 바꾸면 스냅샷을 바꿀 수 없으므로 **세션별 목표 변경을 담을 필드(예: set override) 또는 루틴 버전 갱신 API**가 필요 |
| 2 | 기존 정책: 진행·중단된 운동이 있으면 오늘 루틴 상세 수정 금지(커밋 `a42ef2c`). 운동 중 수정 허용으로 정책을 바꿀지 |
| 3 | 결과 리포트의 '목표 대비' 계산 기준(원래 목표 vs 수정된 목표) |
| 4 | 수정 내용을 이어하기(앱 재시작 후 복원)에 포함할지 — 현재 로컬 진행 상태(`WorkoutDraft`)에는 목표 필드가 없음 |
| 5 | 실제 화면은 종목 단위 목표 횟수(`sessions[].reps`)를 사용 → 시안처럼 세트별 목표를 쓰려면 `resolveExercise`를 세트별 목표로 바꾸는 로직 변경 필요 |

권장: 1~4 결정 후 실제 화면은 "이번 세션 한정 로컬 목표 + 서버 override 필드" 방식으로 연결. UI·규칙 코드는 그대로 재사용 가능.

## 2. 자동 일시정지 · 복귀

| 구분 | 상태 |
|---|---|
| UI | `AutoPauseOverlay` — '자동 일시정지' ↔ 운동 상태 2초 간격 전환, '전신이 보이게 뒤로 물러나 주세요', 흰 점선 인식 박스, 메뉴 → 오늘의 운동 루틴 |
| 연결 | **실제 운동 화면 미연결.** DEV 미리보기에서 `자동정지 UI` / `재인식(복귀)` 개발 버튼으로만 표시(감지 아님) |

**재사용 가능한 정보 (조사)**
- 네이티브 모듈: 매 프레임 33개 관절 `[x, y, z, visibility, presence]`, 사람 미검출 시 `[]`.
- 분석기 출력(`frame.result`): `tracking`(`tracking`/`selecting_side`/`tracking_unavailable`), `ignored`. 현재는 코치 음성 필터에만 사용.
- `CameraReadiness`(AI팀): 운동별 필수 관절 확보 상태(`ready`/`observable`, 0.5초 실패 시 해제). 엔진 문서상 **"촬영 시작의 관찰 가능 범위" 용도이며 운동 판정 프레임을 거르는 필터로 쓰지 말 것.**

**역할 구분 제안**
- CameraReadiness = 운동 시작 전 준비(F03).
- 운동 중 이탈 감지 = 별도 감시기. 분석기 입력은 그대로 두고(필터 금지), 화면·타이머만 자동 일시정지.

**결정 필요 (AI팀·기획)**

| # | 항목 | 제안(초안) |
|---|---|---|
| 6 | 일시정지 조건 | 운동 단계에서 `tracking_unavailable` 또는 필수 관절 미확보가 **N초(예: 2초) 연속** |
| 7 | 재개 조건 | 필수 관절 1초 연속 확보 → '복귀 00:05' → 운동 재개(시안 '자세 재인식 성공') |
| 8 | 카운트 처리 | 일시정지 시 기존 수동 일시정지와 같이 `breakContinuity('pause')`, 횟수 보존 |
| 9 | 판정 위치 | 프론트 감시기 vs AI 모듈 제공(예: `tracking` 지속시간 이벤트). 태현님 연동 작업(`workout-session.tsx` 판정부)과 충돌하므로 **함께 구현 필요** |
| 10 | 측면 운동 | 반대편 관절 가림이 잦아 오탐 가능 → 운동별 필수 관절 프로필 필요 |

## 3. 기존 동작·디자인 보완

| # | 항목 | 처리 |
|---|---|---|
| 11 | 횟수 링·타이머가 시안보다 큼 | **반영.** 링 112→96pt, 숫자·타이머 46→40pt, 상단 영역 높이 축소(132+150 → 116+120) |
| 12 | 상단 HUD·하단 pill 비율·여백 | 상단 축소 반영. pill(높이 60, 좌우 12)은 유지 → 실기기 재확인 |
| 13 | 스켈레톤 색·위치 | 색: F03와 같은 흰색 계열(시안). 위치: 기존 좌표 변환 그대로(코드 변경 없음) → 실기기 재확인 |
| 14 | 시간 운동 AI 유효 자세 유지 시간 누락 | **반영.** 진행 바 아래 '유효 자세 유지 mm:ss'(기존 측정값 `holdSeconds`) |
| 15 | '세트 N 완료!' 3초가 휴식에 포함 | **미반영(타이머 변경 필요).** 방법: (a) 휴식 단계 시간에 3초 추가 → 휴식 누적 시간도 +3초, (b) `sessionFlow`에 세트 완료 단계 추가. 둘 다 단계·시간 기록에 영향 → 결정 필요 |
| 16 | 준비·휴식·일시정지 중 카메라 상시 동작 | 판정 영향 없음(`handlePoseFrame`이 운동 단계·비일시정지에서만 처리). 영향: 배터리·발열, 준비·휴식 중에도 MediaPipe 추론(약 15fps). 장점: 세트마다 카메라 재시작 없음. 장시간 실기기 측정 필요 |
| 17 | 종료 문구와 실제 동작 | 일치: '운동 종료' 시트 = 기존 저장 후 나가기(진행 상태 임시저장, 서버 상태 PAUSED, 오늘 이어하기 가능) ↔ 문구 "기록은 임시저장됩니다 / 오늘 언제든 다시 시작". 단, 기록을 확정하는 '완전 종료'(ABANDONED) 경로는 없음 |

## 5. 충돌 주의

- F03 공용 파일(`workout-preparation/*`, `pose/PoseSkeletonOverlay`)과 AI·서비스·스토어 파일은 **수정하지 않음**(재사용만).
- `workout-session.tsx`는 import·화면 조합(`renderStage`)만 변경, 판정·타이머·저장 구간은 원본과 동일. 태현님 작업과 같은 파일이므로 병합 시 확인.
- `sessionConfig.ts`의 `RoutineItem.targets`에 선택 필드 `targetReps` 추가(타입만, 기존 값 영향 없음).
