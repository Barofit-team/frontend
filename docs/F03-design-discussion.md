## 1. 기능·수치 (기존 유지, 결정 필요)

| # | 화면 | 시안 / 설계 주석 | 현재 처리 | 확인 대상 |
|---|---|---|---|---|
| 1 | Step 2 | 합격 각도: 기기 직립 기준 **5~10° 뒤로** 기울어진 상태 | `angleConfig.ts` 임시값 **70° ±2°**(0°=화면 위로 눕힘, 90°=직립 기준) 유지. 같은 축으로 해석하면 70°는 직립에서 약 20° 뒤로 누운 상태(시안 5~10°는 약 80~85°)이나, 축 해석과 센서 부호 모두 실기기 미검증이라 **수치 변경하지 않음** | AI팀 / 디자인팀 |
| 2 | Step 2 | 목표 각도 **1초 이상** 유지 | `holdMs` **1.5초** 유지 | 디자인팀 / 기능 담당 |
| 3 | Step 2 | 완료 후 **2초 뒤** 자동 전환 | 정렬 화면은 유지 시간(1.5초) 동안 보이고, 충족 즉시 Step 3로 전환(별도 2초 지연 없음) | 디자인팀 / 기능 담당 |
| 4 | Step 3 | 완료 후 운동 진행 화면 이동 시점 | 기존 1.5초 후 `router.replace('/workout-session')` 유지 | 확인만 |

## 2. 시안에 없어 판단이 필요한 UI

| # | 화면 | 내용 | 현재 처리 |
|---|---|---|---|
| 5 | 공통 | **음성 안내 버튼**이 시안 헤더에 없음 | 버튼을 숨김. 재생 함수(`handlePressVoice`)는 유지. Step 3 진입 시 자동 음성은 그대로 재생되지만 **Step 1·2 음성 안내는 현재 들을 방법이 없음** → 노출 위치 결정 필요 |
| 6 | 공통 | 개발용 단계 이동 pill(`‹ 1/4 ›`) | 기본 숨김. 개발 빌드에서 `EXPO_PUBLIC_F03_STEP_NAV=1`일 때만 표시 |
| 7 | Step 2·3 | 뒤로가기 버튼 동작이 시안에 명시되지 않음 | 이전 단계로 이동(Android 뒤로가기와 동일). Step 1은 시안대로 닫기만 있음 |
| 8 | Step 3 | 인식 상태 pill(주요 신체 점 n/m, 화면 밖 관절 이름, 안정화 진행 바) | 시안에 없지만 인식 실패 원인을 알려주는 기존 기능이라 **유지**. 어두운 테마에 맞춰 문구 아래 작게 표시 |
| 9 | Step 3 | 안내 문구 | 시안 문구 "전신이 보이게 뒤로 물러나 주세요"를 고정 표시. 판정 엔진의 상황별 메시지는 8번 pill로만 표시. **음성(mp3)은 "전신이 보이게 영역 안에 서주세요"라 화면 문구와 다름** |
| 10 | Step 3 | 점선 박스 색 | 시안대로 흰색 고정. 기존의 상태별 색(주황·초록)은 pill의 점 색으로만 남김 |
| 11 | Step 3 | 대기 상태 스켈레톤 | 시안 대기 화면에는 스켈레톤이 없으나 기존처럼 **대기·완료 모두 표시**(흰색). 대기 상태에서 숨길지 결정 필요 |
| 12 | Step 3 완료 | 상단 버튼 | 시안대로 완료 상태(1.5초)에서 뒤로·닫기 숨김 |
| 13 | 오류 상태 | 카메라 권한 요청·거부·차단, 카메라 오류, 기울기 센서 사용 불가 | 상세 시안 없음 → 기존 안내 카드·"다시 시도" 흐름 유지(색만 F03 기준) |

## 3. 디자인 차이 (F03 범위에서 우선 적용)

| # | 내용 | 적용 |
|---|---|---|
| 14 | 준비 단계 스켈레톤 색(설계 메모: 파란 브랜드 컬러는 운동 중에만) | F03만 흰색 계열 적용. `UserPositionCamera`·`PoseSkeletonOverlay`에 **선택 prop만 추가**했고 기본값은 기존(초록·빨강)이라 F04 영향 없음 |
| 15 | 전체화면 카메라 | 기존 하단 흰 패널 제거 → 카메라가 화면 전체를 채움 |

## 4. AI팀 확인 요청 (전체화면 카메라 영향)

| # | 내용 |
|---|---|
| 16 | 카메라 화면이 세로로 길어지면서 aspect-fill **좌우 크롭이 커짐**. 예: 393×852pt 화면 + 480×640 프레임 → 화면에 보이는 폭은 원본의 약 62%(기존 하단 패널 구조에서는 약 80%). `CameraReadiness`의 화면 밖 판정은 모델 입력 이미지 기준이라, **화면에 안 보이는 손목·발목도 '인식됨'으로 판정**될 수 있음. 판정 로직은 바꾸지 않았음 |
| 17 | 스켈레톤 좌표 변환은 기존 `PoseSkeletonOverlay` 계산(레이아웃 기준 aspect-fill + 좌우 반전)을 그대로 사용하므로 새 화면 크기에서도 정렬됨(실기기 확인 필요) |
